Analyze the provided financial trade document and generate an XML output following the tradeMoneyMarket schema. Extract only the following key elements if explicitly present in the document:

Essential trade details:
- Entity (company name)
- Counterparty (bank name)
- Trade date
- Maturity date
- Currency code
- Amount (nominal)
- Interest type (Linear/Actuarial)
- Basis calculation (ACT/365, 30E/360, etc.)

For the Entity and Counterparty, once you have extracted the name of the entity or counterparty from the pdf, find the best matching name from the attached reference data (entities-name.txt) and use it in the XML output. When matching:
1. Look for exact matches first
2. If no exact match, look for close matches considering:
   - Case-insensitive comparison
   - Contained strings
   - Similar words/tokens
   - Common abbreviations/variations
3. If multiple possible matches exist, use the best one
4. If no good match is found, use the original name

Payment structure:
- Interest frequency (1M, 3M, 6M, 12M, or IF for in fine)
- First interest payment date (find in the schedule table, the date of the first row in which an interest is payed, and for that look at the columns which contain the word which corresponds in the document language to "interest")
- Amortization frequency (1M, 3M, 6M, 12M, or IF for in fine if the nominal is entirely reimbursed at the end date)
- First amortization date (date where the nominal amount starts to decrease)
- Amortization type (CA for Constant, LA for Linear, IF for In Fine)

Interest details:
- Fixed/Floating rate indicator
- Rate reference (e.g., EURIBOR3M) if floating
- Fixed rate value (if applicable)
- Spread if the document specified a value of spread to add to the fixed rate or to the reference rate 
- Capitalized if the document specified that interests are capitalized (In this case, the nominal value of the transaction increases after each interest calculation) 

Grace periods
 - Interests grace periods (if first interest payment date - trade date >= 2 * interest frequency, then calculate the number of frequencies and give the result under the form "2", "3", etc). If (first coupon date - tradeDate) < frequency shortname, then interest grace periods is let empty
 - Principal grace periods (if first amortization date - trade date >= 2 * amortization frequency, then calculate the number of frequencies and give the result under the form "2", "3", etc). If principalFrequency shortname ="in fine" or if (first amortization date - trade date) < principal frequency,then principal grade periods is let empty

Critical interest-rate XML rules (use exactly one pattern):
- Floating/indexed: <isFixed>false</isFixed>, <rate shortname="INDEX_SHORTNAME"/> (e.g. EURIBOR3M), numeric <spread>. Never output <fixedRate>. Never put an index name in <fixedRate>.
- Fixed: <isFixed>true</isFixed>, numeric <fixedRate> only. Never output <rate>.

Floating example:
  <isFixed>false</isFixed>
  <rate shortname="EURIBOR3M"/>
  <spread>0</spread>

Fixed example:
  <isFixed>true</isFixed>
  <fixedRate>3.5</fixedRate>
