Analyze the provided financial trade document and generate an XML output following the tradeMoneyMarket schema. Extract only the following key elements if explicitly present in the document:

Essential trade details:
- Entity (company name)
- Counterparty (bank name)
- Trade date
- Maturity date
- Currency code
- Amount (nominal)
- Interest type (Linear/Actuarial)
- Basis calculation (ACT/365, 30E/360, etc.)

Payment structure:
- Interest frequency (1M, 3M, 6M, 12M, or IF for in fine)
- First interest payment date (find in the schedule table, the date of the first row in which an interest is payed, and for that look at the columns which contain the word which corresponds in the document language to "interest")

Interest details:
- Fixed/Floating rate indicator
- Rate reference (e.g., EURIBOR3M) if floating
- Fixed rate value (if applicable)
- Spread if the document specified a value of spread to add to the fixed rate or to the reference rate 
- Capitalized if the document specified that interests are capitalized (In this case, the nominal value of the transaction increases after each interest calculation) 

Grace periods
 - Interests grace periods (if first interest payment date - trade date > 2 * interest frequency, then calculate the number of months and give the result under the form "3M", "4M", etc). If (first coupon date - tradeDate) < frequency shortname, then interest grace periods = "0M"

Critical interest-rate XML rules (use exactly one pattern):
- Floating/indexed: <isFixed>false</isFixed>, <rate shortname="INDEX_SHORTNAME"/> (e.g. EURIBOR3M), numeric <spread>. Never output <fixedRate>. Never put an index name in <fixedRate>.
- Fixed: <isFixed>true</isFixed>, numeric <fixedRate> only. Never output <rate>.

Floating example:
  <isFixed>false</isFixed>
  <rate shortname="EURIBOR3M"/>
  <spread>0</spread>

Fixed example:
  <isFixed>true</isFixed>
  <fixedRate>3.5</fixedRate>

Generate XML output using this template (append the floating or fixed interest fragment above, not both):

<tradeMoneyMarket interestGracePeriod="[INTEREST_GRACE_PERIODS]">
  <entity name="[ENTITY]"/>
  <cpty name="[COUNTERPARTY]"/>
  <tradeDate>[TRADE_DATE]</tradeDate>
  <maturityDate>[MATURITY_DATE]</maturityDate>
  <currency1 shortname="[CURRENCY]"/>
  <amount1>[AMOUNT]</amount1>
  <basis shortname="[BASIS]"/>
  <frequency shortname="[INTEREST_FREQ]" customDictionaryName="frequency"/>
  <firstCouponDate>[FIRST_INTEREST_DATE]</firstCouponDate>
  <interestType shortname="[INTEREST_TYPE]" customDictionaryName="interestType"/>
</tradeMoneyMarket>


Only generate the xml, nothing else. Do not include a <tradeType> element; the application adds it from the user's selection. Only include elements where values are explicitly found in the document. Skip any elements where information is uncertain or missing. Format all dates as ISO 8601 (YYYY-MM-DDTHH:MM:SS.SSSZ).
If the PDF cannot be parsed (e.g., no extractable text, unreadable/corrupted content, or parsing failure), output exactly the following single-line XML and nothing else:
<error code="422" reason="UNPARSABLE_DOCUMENT"/>
